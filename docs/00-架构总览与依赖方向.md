# 00 · 架构总览与依赖方向

> 校准基准：v0.2.2（2026-10-01）。本文与 `src/` 实际代码逐文件核对，源码变更时先改这里。

## 项目定位

本地协议网关：对外暴露 OpenAI Chat / Responses 与 Anthropic Messages 兼容 API
（均支持流式），对内适配三条 Qoder 上游链路，供 Claude Code、CC Switch、
OpenAI SDK 等客户端直连。学习研究用途，非 Qoder 官方项目。

## 技术栈基线

| 项         | 取值                                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 运行时     | Node `>=24.21.0`，原生 type stripping 直接执行 `.ts`，**无构建步骤**                                                                         |
| 运行时依赖 | **零**（仅 Node 标准库）；devDeps 仅 oxlint / oxfmt / typescript / @types/node                                                               |
| 包管理     | pnpm 12.6.0（`packageManager` 字段固定）                                                                                                     |
| 质量门     | `pnpm typecheck`（tsc strict 0 错误）→ `lint`（oxlint 0 警告）→ `format:check`（oxfmt）→ `node scripts/architectureCheck.ts` → `node --test` |

类型代码禁用 enum、namespace、构造函数参数属性与装饰器——type stripping
不转译这些语法。TS 版本约束见 `tsconfig.json`（strict + nodenext + noEmit）。

## 目录结构与职责

```text
src/
├── index.ts / bootstrap.ts        启动入口、--provider 组装
├── config.ts                      环境变量 → AppConfig（含模型表）
├── core/                          Canonical Request/Event、Provider Contract、
│                                  能力协商、聚合、错误码 —— 路由层唯一认识的语言
├── protocols/openai/              Chat / Responses 的入站解析与流式 wire 出站
├── protocols/anthropic/           Messages 的入站解析与流式 wire 出站
├── routing/                       Provider Registry、显式模型路由
├── server/                        HTTP 路由、SSE 写出、错误映射（进站方向）
├── sse.ts                         上游 SSE 解析（Provider 方向进站）
└── providers/
    ├── gateway/                   Qoder 客户端 Gateway 私有协议（默认链路）
    ├── cli/                       本地 qodercli 子进程（stream-json）
    └── cloudAgents/               Cloud Agents 官方 API（v0.1 起的原始链路）
```

## 依赖方向硬约束

`scripts/architectureCheck.ts` 在 CI 中强制，违反即红：

- `protocols/*` 不依赖 `providers/*`；`providers/*` 不依赖 `protocols/*`。
- `routing/*` 只认识 `core/` 的 contract（`QoderProvider`），不感知具体 Provider。
- Provider 私有协议细节（codec、auth、wire 形状）不离开各自目录，
  server 层不出现任何上游协议细节。
- 三个方向在当前源码全部成立（CI 输出 `ALL DEPENDENCY RULES PASS` 与
  `NO PROTOCOL DETAIL LEAKS IN SERVER`）。

## 一次请求的生命周期

```text
客户端（OpenAI / Anthropic SDK）
    │  POST /v1/chat/completions | /v1/responses | /v1/messages
    ▼
server/server.ts ── 鉴权（Bearer proxyApiKey）→ 路由分发 → 读 body
    │  resolveModel：显式路由命中 → { provider, model }；未命中 → 直通默认 Provider
    ▼
Provider.stream(CanonicalRequest, ProviderContext)   ← 出站适配（providers/*）
    │  私有协议 → Canonical Event（AsyncIterable）
    ▼
protocols/* ── Canonical Event → 下游 wire（SSE chunk / Responses 事件 / Messages 事件）
    │
    ▼
客户端收到流式响应（或经 core/aggregate.ts 聚合为非流式 JSON）
```

非流式响应没有第二套执行路径：`core/aggregate.ts` 消费同一个 `stream()`。
