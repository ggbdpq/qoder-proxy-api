# 07 · 提交与分支约定

> 任何提交（含 AI 协作产出）先对照本文档；发现历史提交违反约定时，
> 只在改写历史已有授权的前提下修正，不顺手改。

## 分支模型

| 分支      | 角色       | 规则                                              |
| --------- | ---------- | ------------------------------------------------- |
| `main`    | 稳定发布线 | 只接受从 develop 合入的发布快照与 tag；不直接开发 |
| `develop` | 开发集成线 | 日常开发与实验默认在此；每个提交保持可运行        |

发布流程：develop 上确认六项检查全绿（typecheck / lint / format:check /
test / architecture check / demo）→ 打 `vX.Y.Z` tag → 快进合并到 main →
推送。tag 语义：patch = 修复与文档，minor = 新能力，major = 破坏性变更。

## 提交格式（Conventional Commits 简化版）

```text
<type>(<scope>): <中文祈使句标题，≤72 字符>

[可选正文：动机、关键取舍、副作用。空行分隔。]
```

### type 词表

| type       | 用途                                    |
| ---------- | --------------------------------------- |
| `feat`     | 新能力（含新 Provider、新端点、新脚本） |
| `fix`      | 修复缺陷（行为与既定语义不符）          |
| `docs`     | 仅文档与注释                            |
| `test`     | 仅测试增删改                            |
| `refactor` | 不改行为的结构调整                      |
| `build`    | 依赖、工具链、构建与脚本配置            |
| `ci`       | CI/CD 流水线配置                        |
| `chore`    | 其他杂务（不落入以上类别的维护动作）    |
| `perf`     | 性能优化（不改行为）                    |

### scope 规则

scope **必填**，小写简单英文单词，与改动主体对应；禁止用仓库名
（历史上的 `feat(qoderProxyApi)` 无信息量，已废弃）。常用 scope：

| scope                                                     | 范围                                                    |
| --------------------------------------------------------- | ------------------------------------------------------- |
| `ts`                                                      | TypeScript / 类型体系 / 全仓语言层迁移                  |
| `demo`                                                    | 离线演示（`scripts/demo.ts`）                           |
| `server`                                                  | HTTP 服务层（`src/server/`）                            |
| `gateway` / `cli` / `cloud`                               | 对应 Provider（`src/providers/`）                       |
| `routing`                                                 | 模型路由（`src/routing/`）                              |
| `deps`                                                    | 依赖与工具链（package.json / lockfile / lint / format） |
| `workflow`                                                | CI 流水线文件（type 为 `ci` 时常用）                    |
| 文档主题词（`architecture` / `convention` / `readme` 等） | type 为 `docs` 时按文档主题取                           |

横跨多模块的变更取**主导语义**的那个 scope，正文里说明辐射面。

### 粒度与纯度

- 一次提交只做一件事：`fix` 不夹带 `refactor`，`docs` 不夹带代码。
- 新增文件一旦提交就不要在后续提交里删除重写；分组前先想清楚归属。
- 提交前跑六项检查；测试红不提交（修行为的提交先带"修前会挂"的测试）。

## Maintenance Mode（v0.3.0 起）

qoder-proxy-api 已完成 Phase 0-4，作为简历资产进入冻结维护：

- 只接受缺陷修复、文档校准与真实凭证的 live smoke 结果更新；
  不新增 Provider、不做功能扩张、不大规模重构。
- 缺陷修复按 patch 递增（v0.3.1、v0.3.2…）；minor 版本保留给
  不可逆的维护性决策。
- 任何提交仍需六项检查全绿；改测试前先更新 docs/06 证据索引。
