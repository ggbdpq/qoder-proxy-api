# 04 · 模型 Registry 与显式路由

> 事实来源：`src/routing/providerRegistry.ts`、`src/routing/modelRouter.ts`、
> `src/server/server.ts`（路由应用点）、`src/bootstrap.ts`（组装）。

## Provider Registry（`providerRegistry.ts`）

`createProviderRegistry()`：`register()`（经 `assertProvider` 校验，重复 id
拒绝）、`get()`（未知 id 显式抛错）、`ids()`。路由层只见 `QoderProvider`
合同，不感知具体实现。

## 显式路由是唯一路由方式

```jsonc
// QODER_MODEL_ROUTES（JSON，键为客户端可见别名）
{
  "qoder-cli-u": { "provider": "cli", "model": "ultimate" },
  "qoder-qwen": { "provider": "gateway", "model": "Qwen3.7-Max" },
}
```

- `QODER_MODEL_ROUTES`：显式指定别名 → `{ provider, model }`，同别名覆盖。
- `QODER_MODEL_MAP`（v0.1 兼容）：别名一律归属 cloudAgents（`model` 缺省
  取别名本身）。
- 解析规则：别名命中显式路由 → 该 provider + 路由后的 `model`；未命中 →
  **直通默认 provider**（`--provider` 决定，缺省 gateway），原模型名交给
  其模型解析器裁决（未知即 400 `unknown model`）。
- **没有 Provider 自动 fallback**：这是路由策略而非故障切换，任何上游
  失败原样报错。

## server 层的应用语义（易错点）

`server/server.ts` 的请求处理：

```ts
const resolved = await resolveModel(registry, modelRoutes, requested, { defaultProviderId });
await route.handle({ req, res, body, model: resolved.route.model, run });
```

传给协议层的是 `resolved.route.model`——**显式路由命中时是路由后的目标
模型**，直通时等于原别名。此字段在 v0.2.1 前曾被错误地传成客户端别名
（provider 收到的不是目标模型），由 server 层路由集成测试
`test/server/modelRoute.test.ts` 锁定（显式改写 + 直通透传两用例）。

## 错误

| 场景                                       | 结果                                |
| ------------------------------------------ | ----------------------------------- |
| 别名路由到的 provider 未注册               | `MODEL_NOT_FOUND`（含路由目标说明） |
| 直通后 provider 不认识模型名               | `MODEL_NOT_FOUND`（下游 400）       |
| `QODER_MODEL_ROUTES` 非 JSON / 缺 provider | 启动即抛错，拒绝带病运行            |

## 组装（`bootstrap.ts`）

`--provider=<gateway|cli|cloud-agents>`（或 `QODER_DEFAULT_PROVIDER`）决定
注册哪个 Provider 作为默认；`createServer` 亦接受注入式 deps
（providerRegistry / modelRoutes / defaultProviderId / qoderClient /
sessionStore / cloudAgentsProvider），`pnpm demo` 即用注入方式同时装配三条
链路。
